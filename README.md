# WAGhack

現在地を地図で確認し、訪れた市区町村と地域の豆知識を記録できるiOS 26向けSwiftUIアプリです。

## 機能

- MapKitによる現在地表示
- CSVの市区町村マスタ（1965件）を起動時にSwiftDataへ同期
- マップ下部の記録ボタンから現在地を市区町村単位で保存
- 同じ市区町村を再保存した場合は、重複させず保存日時と座標を更新
- 保存した場所を地図上のマーカーで表示
- SwiftDataによる市区町村マスタ、住所・座標・保存日時の永続化
- 全国・都道府県ごとの市区町村踏破率、達成状況、次の目標を表示
- 都道府県別の図鑑で、訪問済み・未訪問を絞り込み
- 市区町村の訪問削除、未訪問も含む豆知識詳細の表示
- 豆知識の空欄は補完せず空欄のまま表示
- iOS 26のネイティブタブバーとLiquid Glass表現
- BGMと記録時の効果音(音量は設定画面でBGM・効果音ごとに調整)

## 画面構成

- **マップ**: 現在地、保存済みマーカー、市区町村保存ボタン
- **市区町村**: 全国の旅の記録 → 都道府県別の図鑑 → 市区町村の豆知識。訪問済み行のスワイプで訪問を削除

## 実行時の注意

初回起動時に位置情報の使用許可を求めます。シミュレータで確認する場合は、Simulatorの位置情報メニューからテスト用の現在地を設定してください。

市区町村マスタはリポジトリ直下の `LocalGovernmentCodeJapan_Knowledge.csv` をアプリへ同梱し、起動時に行政区域コードをキーとしてSwiftDataへ同期します。CSVを更新した場合は、次回起動時に既存マスタも更新されます。

## 2026年9月12・13日: 旅の図鑑

作業ブランチ: `feature/2026-09-12-13-saved-places-gamification`

### 踏破率の規則

- 分母は同梱マスタ内の対象市区町村数。都道府県行と、区を持つ政令指定都市の親市行は除外する。
- 政令指定都市は区単位、東京都の特別区は区単位、その他は市町村単位。行政区域コードで重複排除する。
- 分子は対象コードと訪問済みコードの共通部分。全国の率は市区町村数の合計から求める（都道府県の率の平均ではない）。
- 親市だけの記録から区の訪問は推測しない。未照合・集計対象外の記録は全国画面の別欄に残し、確認・削除できる。
- 25・50・75・100%の節目と、次の節目までの市区町村数を表示する。達成表示は現在の記録から導出し、削除すると戻る。
- マスタ更新で対象数が変われば率も変わる。固定の自治体総数や面積割合ではない。

### 責務とデータフロー

`SwiftData → @Query → SavedPlacesStore → ExplorationProgressCalculator → 各View`

- `ExplorationProgress.swift`: SwiftData/SwiftUIに依存しない集計用の値型、対象判定、率、節目計算。
- `SavedPlacesStore.swift`: Query結果を集計入力へ変換し、削除・保存失敗時のrollbackを担当。進捗を永続化・二重保持しない。
- `SavedPlacesScreen.swift`: 全国サマリー、都道府県一覧、集計対象外の記録。集計は自分で計算せず、`MapScreen`が持つ`summary`を受け取る（シートを広げるたびに全市区町村を読み直すとメインスレッドが約0.1秒止まり、展開のアニメーションが引っかかっていたため）。
- `PrefectureExplorationScreen.swift`: 都道府県の図鑑と訪問状況の絞り込み。
- `ExplorationProgressCard.swift`: 共通の進捗表示と都道府県行。標準のProgressViewと可変文字サイズを使用。
- `MunicipalityDetailScreen.swift`: 訪問の有無に依存しない豆知識詳細。

SwiftDataのQueryを取得層として維持し、単一実装だけのRepository/protocolは追加しない。
永続モデルの変更、新規依存ライブラリの追加はなし。既存のiOS 26.2以上のアプリ設定に合わせる。

### 検証

`ExplorationProgressTests`で空データ、政令市・特別区、全国の加重集計、重複コード、節目の切り上げ、フィルター、SwiftDataでの訪問削除を検証する。

## MAPアップデート: 探索と記録

ブランチ: `feature/2026-09-12-13-map-exploration`（図鑑ブランチから作成）。

- 起動時に現在地の市区町村を確認し、下部カードで訪問状況と記録ボタンを表示。
- 訪問済みピンをタップすると、選択色、最終訪問日、豆知識へのシートを表示。選択解除で現在地カードへ戻る。
- 上部は現在地または選択ピンの都道府県進捗。未特定時は全国の訪問都道府県数を表示。
- 記録操作では現在地を再取得する。選択中のピンや古い位置を保存しない。
- 初訪問・再訪問・25/50/75/100%達成を区別。成功時はカード内に結果を表示し、確認アラートを出さない。
- ピン選択・保存成功・失敗に標準触覚フィードバック。実際の振動は対応する実機で確認する。
- 現在地の再確認ボタン、読み込み状態、再試行可能なエラーを表示。位置情報を許可しなくても保存済みピンの閲覧は可能。
- Reduce Motionに対応。カードはスクロール可能で、大きな文字でも操作へ到達できる。

### MAPの責務分離

`MapScreen`はQueryと選択・カメラを所有し、`MapViewModel`が位置取得・住所照合・処理状態を管理。
`MapVisitRecorder`が保存と再訪問更新、保存失敗時のrollback、節目判定を担当する。
`MapExplorationCards`は状態と操作クロージャを受け取って描画する。
共有集計と豆知識画面は`Shared/Exploration`へ移し、図鑑とマップから利用する。
進捗は永続化せず、SwiftDataの最新記録から導出する。永続モデルや外部依存は変更しない。

未訪問ピンは未実装。行政区域の塗り分けは下記「市区町村パズル」を参照。
現在地カードは起動時・明示的な再確認時に加え、地図画面を開いている間は移動に合わせて更新する（下記「移動中の市区町村の自動判定」）。アプリがバックグラウンドにある間の追跡はしない（裏では粗い位置で初めての市区町村・都道府県だけを知らせる。下記「初めての市区町村で通知」）。

## 2026年9月23日: 市区町村パズル（境界ポリゴン）

ブランチ: `feature/2026-09-23-silverweek`。マップに市区町村と県境を重ね、訪問済みの市区町村を塗りつぶす。
訪れるたびにピースが埋まっていく体験の土台。

- 訪問済み: ティールで塗る（アプリのテーマ色）。未訪問: 塗らず、薄いグレーの網目（市区町村境の線）だけで示す（2026-11。下記「重さへの対策」）。どちらも縁の線は0.6〜2.8ptで、常に県境より細い（区別は太さと色の両方で付く）。現在地: ティールの太い縁取り（2.5〜4.2pt、常に県境より太い）。
- 線の太さは縮尺で変える（`BoundaryLineWidths`）。1ptあたりのmの対数で補間し、全国表示（約3,000m/pt以上）で最も細く、市区町村全体が収まる縮尺（約60m/pt以下）で最も太くする。カメラが止まったときだけ8段階に丸めて更新する（動かしている最中や小さな変化で全ピースを描き直さないため）。段の境目を約0.25段ぶん越えるまで今の段を保つヒステリシスを入れ、太さはピースの入れ替えと同じ更新で書き換える（`MunicipalityPuzzleStore.lineWidths`。2026-11）。記録・脈打ちの演出の線も同じ倍率で太らせる。
- 県境・海岸線: 境界データの`prefectureLines`（線）を`MapPolyline`で描く。市区町村の線より太い不透明の灰色（全国表示1.2pt〜市区町村の縮尺4.0pt）で、主に太さと色味で市区町村の線と区別する。線の継ぎ目は丸める（鋭角がトゲ状に伸びるのを防ぐ）。1本の県境はデータ上1回しか入っていないので二重に描かない。
  - 線には`mapOverlayLevel(.aboveLabels)`を付けない（付けると線が描かれない。iOS 26.5シミュレータで確認）。現在地の縁取り（ポリゴン）だけ`.aboveLabels`に置く。
  - 以前は都道府県ポリゴンの外周を県境として描いていた。元データのすき間で県が複数のポリゴンに分かれていた場所（千代田・中央・港区の外周、田原市と豊橋市の間など8か所）に、県内なのに県境の線が出ていた。データ生成で`-clean`を入れ、県境を線データにして解消した。
- 穴（飛び地）のある形: MapKitは穴のあるポリゴンの縁取りを、同じ太さを指定しても太くぼやけて描く（iOS 26.5シミュレータで確認）。そのため川越市・小金井市など飛び地を囲む市区町村や、東京都などの訪問済みの縁取りだけが、引いたときに県境のような太い線に見えていた。穴のあるピースは、塗りを穴付きのポリゴン（縁取りなし）で描き、縁取りは外周と各穴をそれぞれ穴の無いポリゴンにして描く（`BoundaryPiece.outlines`）。線（`MapPolyline`）にしないのは、`.aboveLabels`に置けず灰色の県境の下に隠れることがあるため。
- 表示モード: 踏破率ヘッダー上部のセグメント（市区町村｜都道府県）で切り替える（ヘッダーの横スワイプでも可）。市区町村では市区町村のピースを塗り、都道府県では都道府県ごとの制覇率で塗り分け、市区町村のデータは読み込まない。選択は`@AppStorage("map.progressPage")`で端末に保存（初期値は都道府県）。都道府県ページのままユーザーが画面幅40km以下まで拡大すると、市区町村ページへ自動で切り替える（`MapProgressPageZoomPolicy`。アプリが動かしたカメラでは切り替えない＝`MapCameraPosition.positionedByUser`で判定）。引いたときに都道府県ページへ戻す自動切り替えはしない。記録の儀式では、記録する単位に合わせてアプリが表示を切り替える（2026-10-22）。「日本」と初めての都道府県の儀式では都道府県ページ（都道府県の儀式では県全体へ寄せる）、その後に続く市区町村の誘いでは市区町村ページ（市区町村全体へ寄せる）にし、保存する選択も書き換える。初回の日本→都道府県→市区町村の流れで、地図の単位を記録の順に合わせるため。起動直後など都道府県が不明な間は保存値を書き換えずに都道府県ページを見せ、分かり次第保存した選択へ戻す。以前あった右上の境界メニュー（市区町村と県境／県境のみ）は、ヘッダーの切り替えと役割が重なるため廃止した。
- ピン表示: 地図右下の丸ボタンで、記録した場所のピンの表示／非表示を切り替える。選択は`@AppStorage("map.showsPlacePins")`で端末に保存（初期値は表示）。再記録直後の吹き出しはピンを隠していても出す。
- 交通の表示: 地図右下の丸ボタンで「道路」（Apple標準の地図のまま）と「線路」（地図の強調を`.muted`で抑えて線路を道路に埋もれにくくし、施設は駅などの公共交通だけに絞る）を切り替える。MapKitには「マップ」アプリの交通機関表示が公開されていないため、この組み合わせで近づけている。選択は`@AppStorage("map.transportLayer")`で端末に保存（初期値は道路）。
- 塗り分けはSwiftDataの`SavedPlace`から毎回導出し、ポリゴン側に訪問状態を持たない。記録を削除すると塗りも戻る。
- 政令指定都市は区のコードで記録されるため、区のピースが埋まる。親市だけの記録では塗らない（踏破率の規則と同じ）。
- 出典（国土数値情報 N03、CC BY 4.0）は「設定」画面の末尾に`attribution.txt`の文面で表示する。
- 進捗に添える小さな地図（記録済みの区画をティール、未記録を薄い灰色で塗る）。
  - 踏破率ヘッダー（56pt）: 市区町村ページに現在地の都道府県、都道府県ページに日本地図。
  - 旅の記録シート（96pt）: 進捗の隣に日本地図。都道府県シート（96pt）: 進捗の隣にその県（市区町村ごとに塗り分け）。
  - 市区町村詳細シート: 見出しの下に、その市区町村の形を高さ220ptで大きく描く。塗らずにティールの縁取り（2.5pt、淡い影付き）だけにする。形はリストの背景に固定して描き、リスト先頭には同じ高さの透明な行を置く。スクロールするとカードが形の上に覆い被さる。
  - 塗りは踏破率と同じデータで決める（都道府県は`ExplorationSummary.visitedPrefectures`、市区町村は`PrefectureExploration.visitedCodes`）。
  - 使うデータ: 日本地図はLOD0（起動後に1回）、県の地図は県ごとのLOD1、市区町村の形は県ごとの最も細かいLOD（詳細を開いたときだけ）。
  - `SilhouetteMapStore`（`MapScreen`が所有し、シート内の画面へはenvironmentで渡す）が読み込み、`BoundarySilhouetteBuilder`で描画サイズに合わせて間引いた地図を保持する。作った地図は残し、同じ県・市区町村では読み直さない。地図用の`MunicipalityPuzzleStore`とはリポジトリを共有しない（キャッシュのフィルタ前提が異なるため）。
  - 間引き: 描画サイズに対して許容誤差0.4pt。描画時は頂点の中点を曲線でつないで角を丸める。1.5ptまで粗くすると県の形が分からなかった。
  - 日本地図は北海道〜九州を本体とし、沖縄県は左上の小窓に縮尺を変えて描く。奄美・小笠原など本体の範囲外の離島は描かない。
  - 県の地図の枠は最大ピース（本土）に合わせる。描くのは本土に載っている区画と、県の地図の大きさに対して10%以上の大きな島（佐渡島・淡路島など）だけで、小さな離島だけの町村は描かない。この省略は小さな地図だけで、メインの地図のパズルでは島も描く。
  - 読み込み前も枠の大きさは確保する（地図が現れたときにレイアウトが揺れないように）。Listの行は中身が空だと行ごと省かれ`.task`も動かないため、透明な下地を置く。

### LODと描く内容

`manifest.json`の`lodTransitions`（拡大時と縮小時で閾値が異なるヒステリシス付き）で、カメラ停止時の画面横幅からLODを決める。

| LOD | 画面横幅の目安 | 市区町村 | 県境 |
|---|---|---|---|
| 0 | 約800km〜4,000km（全国） | 訪問済み・現在地だけ | 描く |
| 1 | 約200〜800km | 訪問済み・現在地だけ | 描く |
| 2 | 約50〜200km | 約120km未満で未訪問の網目（線）も描く（それより広い間は訪問済み・現在地だけ） | 描く |
| 3 | 約17〜50km | 訪問済み・現在地のピース＋未訪問の網目（線） | 描く |
| 4 | 〜約17km | 訪問済み・現在地のピース＋未訪問の網目（線） | 描く |

未訪問の網目を描くかはLODとは別に`UnvisitedMunicipalityVisibility`が決める（拡大時120km未満で描き始め、縮小時150km超で消す）。

4,000kmより広い範囲（日本が画面の一部にしか映らない縮尺）では何も描かない。

### 重さへの対策

MapKitはポリゴン1枚ごとに描画を持つため、枚数がそのまま重さになる。

- 未訪問の網目は画面の横幅が約120km未満まで寄ったときだけ描く。全国で約2,000枚・LOD1で約1,500枚だったものが、県境・海岸線（全国で約180本）と訪問済みの枚数だけになる。以前はLOD2に入った時点（180km未満）で描いており、1画面に最大約600枚が載って重かったため、2026-10に閾値を寄せた（面積比で約0.44倍）。
- 未訪問の網目は、市区町村ごとのポリゴンではなく線で描く（2026-11）。以前は未訪問の市区町村を1つずつ透明のポリゴン（縁取りだけ）で載せており、iPhone 13で県表示と市区町村表示が切り替わる縮尺付近が重かった（東京中心・390×844ptで横幅119kmのとき約550枚、150kmで約635枚。隣り合う境は両側から2回描かれ、穴のあるピースは塗り用＋輪郭用で数枚になる）。
  - 境界データに県内の市区町村どうしの境だけを持つ線レイヤ`municipalityLines`（LOD2〜4）を足した。SwiftUIの`Map`には複数の線を1枚にまとめる型（`MKMultiPolyline`）が無いため、データ生成時に県ごと・つながった境ごとに一筆書きにした1本の線にしてある（行き止まりの境は往復する。頂点は約3割増える）。
  - 1本の線の中で往復した区間は、半透明（gray 35%）でも濃く見えない（iOS 26.5シミュレータで確認）。
  - 地図に載る枚数（東京中心・390×844pt、訪問済み0）: 119kmで595→83枚、150kmで679→85枚（県境・海岸線約45本を含む）。
  - 訪問済み・現在地・演出中の市区町村はこれまでどおりポリゴンで描く。網目は最初に置き、訪問済みの線と県境がその上に来る。
- 画面幅の1/100（約4pt）未満の島は描かない。輪郭線を付けると点の塊になり、海岸沿いに並ぶと線が太い帯に見えるため。各行政単位の最大のピースだけは縮尺に関係なく必ず描く。
- ピースのidにはLODを含める。含めないとLODが変わってもidが同じになり、地図側が古いLODの形を残したまま新しい形を重ねる。簡略化の違う2本の線が重なって、境界の一部（それまでに別のLODで表示した範囲）だけが太い帯に見えていた。
- 先読みする範囲は表示範囲の上下左右20%（以前は50%で、描く面積が約2倍になっていた）。基準の表示範囲はヘッダー・シートの裏も含めた地図のビュー全体（`MapFullFrameRect`）。以前はセーフエリアの内側だけを基準にしていたため、半透明のヘッダーやシートの裏でピースが途切れて見えた。

### 起動直後の待ち時間への対策（2026-09-24）

実機で起動直後、境界と現在地の表示まで長く待たされていた。主な原因は次の2つと見ている（Instrumentsでの計測は未実施）。

- 全国ファイル（LOD0）が1レイヤ約12MB（頂点約50万）あり、その約96%は描かれない小さな島だった。起動時は日本全体が映るため、これを複数レイヤ分デコードしていた。
  → データ生成で、各LODで絶対に描かれない島を捨て、粗いLODの座標の桁を減らした（`BoundaryData/README.md`「小さな島の除去」）。描く規則はアプリの`BoundaryPieceFilter`と同じなので見た目は変わらない。
- 現在地が分かるまでカメラが`.automatic`（ピン全体、多くは日本全体）だったため、まずLOD0を読み、その後で現在地周辺を読み直していた。
  → 最後にカメラが止まった範囲を`MapRegionMemory`（UserDefaults `map.lastRegion`）に保存し、次の起動では現在地が分かるまでその範囲を見せる。初回起動など保存が無いときは従来どおり`.automatic`。
- 地図を現在地へ寄せるのが、住所の確認（`MKReverseGeocodingRequest`、通信あり）の後だった。
  → 起動時の現在地の取得では、座標が分かった時点で地図を寄せる（`MapViewModel.refresh`の`onLocationResolved`）。市区町村の特定と「現在地の市区町村を確認しています…」の表示はその後も続く。
  市区町村が分かったら、ヘッダーのページ（全国/市区町村）によらず、市区町村ページで寄せるときと同じ縮尺（市区町村全体が収まる範囲）へ寄せ直す（2026-10）。その間にユーザーが地図を動かした・ピンを選んだ場合は寄せ直さない。

### 組み込みと注意点

- Xcodeプロジェクトは`BoundaryData/generated/BoundaryData/`の`manifest.json`・`attribution.txt`・`municipalities/`・`prefectures/`・`prefectureLines/`・`municipalityLines/`（フォルダ参照）をバンドル直下へコピーする。都道府県ポリゴンは制覇率の塗りにだけ使う。
  生成物はGit管理外のため、**クローン直後は`BoundaryData/README.md`の手順で再生成しないとビルドが失敗する**。
- 同梱サイズは市区町村・都道府県・県境線レイヤで約188MB（地方レイヤは未使用のため含めない）。
- 市区町村境線レイヤ（`municipalityLines`、LOD2〜4）で約16MB増えた（2026-11。LOD2 2.0MB / LOD3 4.8MB / LOD4 9.1MB）。訪問済みの線や現在地の縁取りと頂点を一致させるため、各LODの形をそのまま持っている。
- 全国の市区町村ファイル（12MB）の初回デコードはMacで約0.7秒かかる。actor上で行い、以降はキャッシュを使う。
- 県境線のデータには海岸線も入っていて、県境と同じ線で描く。全国の県境線ファイル（LOD0）の初回デコードはMacで約1.4秒。
- 訪問済みが数百件になると、全国表示でも同じ数だけポリゴンが増える（すべて埋めると約2,000枚）。
- ポリゴンのタップ選択には対応していない（SwiftUIの`Map`の選択はMarker/Annotationが対象）。
- 実機での描画性能・メモリは未検証。シミュレータ（iPhone 14 Plus / iOS 26.5）で、全国〜LOD3の表示・県境・表示モードの切替を確認済み。
- LODの判定・島の間引き・GeoJSON変換（ポリゴン・県境線）・ファイル選択は`MunicipalityBoundaryTests`で検証する。

### 地図の現在地操作

- 現在地ボタン・交通の表示ボタン・ピン表示ボタンは地図右下、シートの上に縦並びで配置する。いずれも56pt、アイコンはtitle2。
- 現在地ボタンとヘッダーの現在地バッジは、表示モードに合わせた区域の範囲へ移動する。
- 市区町村は表示用の間引きとは独立して、その県の最詳細境界を読み込み、離島・飛び地を含む区域全体に余白を付けて収める。100kmの上限は適用しない。都道府県の縮尺の決め方は維持する。
- 境界を取得できない場合は従来の現在地周辺表示へ戻し、読み込みエラーは開発者ログに残す。

### 移動中の市区町村の自動判定（2026-09-26）

アプリを開いたまま移動して別の市区町村に入ったら、現在地ボタンを押さなくても、既存の「新しい市区町村に入った」演出（脈打ち→誘いシート）を出す。

- `LocationService.accurateLocationUpdates`で`CLLocationUpdate.liveUpdates`を受け、`MapViewModel.monitorMunicipalityChanges`が判定する。市区町村が変わった時だけ`currentVisit`を差し替え、既存の`municipality.code`のonChangeに任せる。
- 判定中も`currentVisit`を消さず、進行状況の表示・エラー・エラーの触覚は出さない（失敗は開発者ログのみ）。
- 電池と通信への配慮:
  - 住所の確認（通信あり）は、前回から**300m以上**移動し、かつ前回の自動判定から**30秒以上**たった時だけ。精度が**100m**より粗い位置は使わない。
  - 3つの値は`MapViewModel`の定数（`automaticCheckDistance` / `automaticCheckInterval` / `automaticCheckMaximumAccuracy`）。仮の値で、実機で歩き・車・電車を試して調整する前提。
  - 地図の`UserAnnotation`のためにGPSは元々動いているので、位置を受ける側を1本足す負担は小さい。静止中はCore Locationが更新を自動で止める。
- 監視するのは`MapScreen.canMonitorMunicipalityChanges`がtrueの間だけ（前面にある・儀式/誘いシートを出していない・現在地が一度は取れている）。**儀式シートを新しく足したら、この条件にも加えること**（表示中のシートの市区町村が書き換わらないようにするため）。
- 誘いシートは、ピン選択中・旅の記録を広げている間は出ない（既存の`handleMunicipalityVisitChange`の判定）。記録を折りたたんだ時に出る。
- 自動判定中に現在地ボタン・記録が始まったら、そちらの結果を優先する（`locationRequestGeneration`で古い結果を捨てる）。
- 移動中の実機での動作は未検証。Simulatorでは Features > Location > Freeway Drive などで確認する。

### 2026-10-12 追加: モードの選択・文言・お知らせ

ブランチ: `feature/notification-modes`。

- **都道府県のみ**: 記録が一度もない都道府県に入ったときだけ知らせ、県内で市区町村が変わっても知らせない。記録済みの判定は地図画面の「初めての都道府県です！」と同じで、県内の市区町村の記録（親市だけの記録も含む）か都道府県だけの記録があれば記録済み。
  判定の規則（同じ区域では通知しない・12時間は再通知しない・前面では通知しない）は市区町村と共通で、`NewMunicipalityAlertPolicy`に区域のコードを渡して判定する。履歴はモードごとに別のキーで持つ。
- **文言**: 「東京都中央区に初訪問です！よりみちを開いて記録しませんか？」／「埼玉県に初訪問です！…」。タイトルは付けない（アプリ名はOSが添える）。文言は`NewMunicipalityAlertMessage`。
- **チュートリアル**: 「初めての街に入ったら、お知らせ」のページを、位置情報の許可を予告する最後のページの直前に追加した。
- **お知らせ（通知の案内カード）**: 1回だけ出し、その場で「市区町村ごと」「都道府県のみ」「今はしない」を選べる。オンにすると通知と位置情報「常に」の許可を求める。
  - 2026-10-22 変更: 出す時機を記録の有無で分けた（`NewMunicipalityAlertAnnouncementGate.Timing`）。起動時に記録がある人（アップデートで来た人）には、従来どおりチュートリアルの後に「通知機能が追加されました」として出す。記録が無い新規の人には、初めて市区町村を記録したお祝いシートを閉じた後に「次の初めての街も、お知らせしましょうか？」として出す（「みどころを見る」で詳細へ進んだ場合は割り込まず、次の初訪問のお祝いの後に回す）。新規の人はチュートリアルから位置情報「使用中」の許可・「日本」の儀式・最初の記録まで途切れずに進み、価値を体験した後で「常に」の許可を求めるため。
  - 版番号ではなく「見たか」（`announcement.newMunicipalityAlert.seen`）を保存するため、新規インストールでも、以降の版から使い始めた人でも1回出る。既にいずれかのモードを選んでいる人（最初の記録までに設定で選んだ人を含む）には出さない。
  - 地図の常駐シートや儀式シートと競合しないよう、シートではなくチュートリアルと同じく`ContentView`のZStackに重ね、表示中は地図を`isActive=false`にしておく。
- **設定の引き継ぎ**: オン/オフだけだった版（`newMunicipalityAlert.isEnabled`）でオンにしていた人は、市区町村モードとして`newMunicipalityAlert.mode`へ移す。市区町村モードの履歴は以前と同じキーを使い、JSONのキー名`lastMunicipalityCode`も保つ。

- 「初めて」の判定は既存の記録（`SavedPlace`の市区町村コード）をそのまま使う。政令指定都市は区のコードで判定し、親市だけの記録では区を記録済みとみなさない（踏破率の規則と同じ）。
- 裏での位置はCore Locationの大幅な位置の変化（significant-change location service）で受け取る。約500m以上の移動でしか届かず、GPSを常時動かさないので電池への負担が小さい。アプリが終了していても、位置が変わればシステムが裏で起動し直す（iOS 26.5シミュレータで、`simctl terminate`後に位置を動かして通知が出ることを確認）。ユーザーがアプリスイッチャーで終了させた場合はOSが起動し直さない。
  - 却下した案: `CLBackgroundActivitySession`＋`liveUpdates`による常時追跡。GPSを動かし続けて電池を大きく使う割に、市区町村単位の判定には精度が過剰。
- 裏で位置を受け取るには位置情報の「常に」許可が要る（`NSLocationAlwaysAndWhenInUseUsageDescription`）。トグルをオンにした時に通知と「常に」の許可を求め、起動時には求めない。足りない許可は脚注で伝え、設定アプリへの導線を出す。
- 前面にある間は地図画面が自前の誘いシートを出すため通知しない。その場合も「知らせた」ものとして履歴に残し、裏へ回った後に同じ市区町村を通知しない。
- 同じ市区町村の中で位置が変わっただけでは通知しない。境界を行き来しても、一度知らせた市区町村は12時間通知しない（`NewMunicipalityAlertPolicy.renotifyInterval`）。
- 判定に使う位置の精度の上限は1,000m（`NewMunicipalityAlertMonitor.maximumHorizontalAccuracy`）。大幅な位置の変化は基地局・Wi-Fiの粗い位置で届くことが多いため、地図画面の自動判定（100m）より緩い。12時間・1,000mとも仮の値で、実機で調整する。
- 通知をタップするとアプリが開き、地図画面が現在地を確認して従来の誘いシートを出す（通知専用の画面遷移は持たない）。

## 有料機能: 自動で記録（2026-10-21）

ブランチ: `feature/auto-record-premium`。初訪問の通知を出すときに、その場所の市区町村を記録まで済ませる。月額200円のサブスクリプションと買い切り1,200円のどちらかで解放する。

## バッジ（Phase 1, 2026-11-03）

ブランチ: `claude/badges-phase1`。旅の記録のシートの上部に「訪問記録｜バッジ」の切り替えを置き、バッジを集める「旅のスタンプ帳」を足した。下部タブは増やしていない。

- バッジは10種類を固定の順で3列（文字を大きくしている時は2列）に並べる。判定できるのは既存の訪問履歴から求められる5種（はじめの足あと・足あとコレクター・県またぎの旅人・地元の探検家・東京23区の旅）。残り5種（都会にこんにちは・ふたごのまち・数字の旅人・超・境目！・三都物語）は「準備中」として絵柄と名前だけを見せ、獲得にはならない。
- 一覧は「集めたバッジ ○ / 10 種類」（段階式のランクの数ではなく種類の数）、次のチャレンジ（次の閾値に最も近いもの）、スタンプ帳の順。詳細は大きなスタンプ・今の状態の1文・ランクごとの達成条件・対象の街（23区のチェックリスト）・地図への導線。
- 段階式のランクはブロンズ／シルバー／ゴールド／プラチナで全バッジ共通。外周の色だけでなく星の数と文字でも示す。
- 新しく獲得すると、地図だけが見えている落ち着いた時（保存中・地図の演出・儀式や誘いのシート・旅の記録・設定を開いている間は待つ）に、スタンプを押す演出のカードを地図の上に重ねる。同時に複数獲得したら1枚にまとめる。「バッジを見る」で詳細（複数ならスタンプ帳）を開く。
- 導入前の訪問履歴による獲得は、最初の評価で日時不明としてまとめて記録し、「これまでの旅で○種類のバッジを獲得しています」を1回だけ出す（1件ずつの演出はしない）。
- スタンプの絵柄は仮（SF Symbols＋色）。アセットに `badge_first_step` のような名前（`badge_<BadgeID>`）の画像を入れると、その画像に置き換わる。

### 責務とデータフロー

`SwiftData → @Query → MapScreen.summary（ExplorationSummary） → BadgeStore.update → BadgeRuleEvaluator / BadgeAchievementReconciler → BadgeStatus → 各View`

| ファイル（`Features/Badges/`） | 役割 |
|---|---|
| `BadgeDefinition.swift` | バッジの識別子・判定の種類・ランク・仮の絵柄の型 |
| `BadgeCatalog.swift` | 10種の定義（名前・閾値・単位・条件文）と、東京23区のコードなどの対象データ。閾値や対象を変えるときはここだけ |
| `BadgeRuleEvaluator.swift` | 集計から進み具合を求める（副作用なし）。数え方は踏破率と同じで、政令指定都市は区、市そのものの記録は数えない |
| `BadgeAchievement.swift` | 保存する獲得記録（最高ランク・獲得日時・知らせ済みの段階）と、進み具合との突き合わせ・知らせの決定（副作用なし） |
| `BadgeStatus.swift` | 進み具合＋獲得記録の画面用の状態と文言、次のチャレンジの選び方 |
| `BadgeStore.swift` | 状態の唯一の持ち主（`MapScreen`の`@State`）。獲得記録はUserDefaults（`badges.ledger`）にJSONで保存 |
| `BadgeStampView.swift` / `BadgeCollectionView.swift` / `BadgeDetailView.swift` / `BadgeUnlockOverlay.swift` | スタンプ・一覧・詳細・獲得の知らせ |

- 進み具合は保存せず、`summary`が変わる時（記録の件数が変わった時）だけ評価し直す。地図の再描画や位置の更新では評価しない。
- 獲得記録はSwiftDataではなくUserDefaultsに置いた。10件ほどの小さな値で訪問記録とのつながりも無く、訪問記録のストアのスキーマを変えるほどの理由が無いため。消えても訪問記録から獲得は取り戻せる（日時と知らせ済みかどうかだけが失われる）。
- 一度獲得したランクは、記録を消しても下げない（`BadgeStatus.earnedTierCount`）。
- マスタの読み込み前（対象の市区町村が0件）には評価しない。その時点で「最初の評価」を済ませると、既存の獲得を取りこぼすため。
- 自動で記録（裏での記録）による獲得は、アプリを開いて集計が更新された時に知らせる。獲得日時はその時刻になる。
- 詳細の「地図で探す」は、東京23区なら23区全体へ、地元の探検家ならいちばん進んでいる県へ地図を寄せるだけ（独自の地図機能は作らない）。
- バッジの詳細は`MapSheetRoute.badge`で旅の記録のシートに積む。地図と並べて見るものではないので、中段の高さは持たせない（`isShowingDetailRoute`から除く）。

## バッジ詳細のパターン（2026-11-03）

ブランチ: `claude/badges-detail-patterns`（Phase 2の上に積んだもの）。ユーザーの資料「旅のクエスト図鑑」の詳細パターン（6〜9章・12章）に沿って、詳細画面の進み具合をバッジの遊び方が見える形に作り分けた。

- 共通の構成: スタンプ・名前・ひとこと → 大きな「今の数 / 目標の数」とゲージ・次の一歩の1文 → バッジごとの見せ方 → 達成条件 → 旅のヒント → 達成の記録（獲得日） → 地図で探す。

- **数字の旅人**（コレクション型）: 一〜十・廿・九十九の12マス。マスを押すと、集めた数字は集めた街を、まだの数字は候補の街と「『六』がつく街を地図で探す」を出す。判定を「名前が漢数字で始まる3か所」から「名前に入っている数字を集める（3 / 6 / 12種類でブロンズ・シルバー・ゴールド）」に変えた。対象は`BadgeCatalogData.numerals`（四万十市は「四」と「十」の両方、九十九里町は「九十九」だけ）。

- 変えていないこと: 旅の記録の「訪問記録｜バッジ」の切り替え、一覧（3列のスタンプ帳）、獲得の知らせのカード。資料の「バッジ図鑑」への入口カード・「めざす／集めた」・カテゴリ・おすすめ3件・コンパクトな通知は、今回の範囲（詳細のパターン）の外にした。

ブランチ: `claude/badges-quad-boundary`（バッジ図鑑の上に積んだもの）。超・境目！の4つ版として「超超・境目！」（`quadruple_boundary`）を足した。全11種。

- 判定: 記録した場所がおたがい1km以内にある4つの市区町村を訪れる（暫定）。超・境目！と同じ`nearbyMunicipalities`で、いくつ集めれば獲得かは`tiers`の最後の値（3・4）で決める。
- 探し方（`NearbyClusterFinder`）: 緯度で並べて1km以内の相手だけを近い記録として持ち、その中で「おたがい近い組」を目標の数まで広げる。1kmの中に入る記録は多くても数件なので、組を探す部分は総当たりでも軽い。
- 詳細の図は目標の数の点を正多角形に置き（3つは三角形、4つは四角形）、すべての点どうしを結ぶ。獲得時の4か所を証跡として保存するのは超・境目！と同じ。
- 既存の記録ですでに条件を満たしていれば、アップデート後の最初の評価で日時不明の獲得として記録し、まとめの知らせを出す（`evaluatedBadgeIDs`）。
