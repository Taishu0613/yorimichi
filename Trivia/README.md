# みどころ・怪奇・都市伝説の文

市区町村シートの「みどころ」カードと「怪奇・都市伝説」カードの文です。市区町村マスタ `LocalGovernmentCodeJapan_Knowledge.csv` の「豆知識(有名なもの)」(みどころ)と「豆知識(歴史)」(怪奇・都市伝説)の列に入ります。みどころの最初の一文は、初訪問の通知の本文にもそのまま使われます。

2026-11-15〜16にユーザーと決めた書き方で、全1,918市区町村を作り直します。お手本は `Trivia/out/b00_examples.json`(渋谷区・新宿区・中央区・横浜市・岡崎市・西尾市・尾張旭市。ユーザー確認済み)です。書く前に必ず読んで、文の調子を合わせてください。

## 書き方

**共通**

- 1枚のカードに話は一つ。名所を並べない(名所の一覧は「この街でできること」が受け持つ)。
- 最初の一文だけで「へえ」となるようにする。40字くらいまで(最大50字)で、単独で読める文にする。
- 二文目以降で「なぜそうなのか」を短く書き、最後はその街のどこで確かめられるか(碑・神社・通り・お店など)で締める。
- 前提知識を前提にしない(2026-11-17 ユーザー指示)。地元の人や詳しい人しか知らない言葉・人物・名物・出来事には、文の中で一言説明を入れる(例:「宿場とは、街道を行く旅人が泊まり、馬を乗り継いだ町のこと」「八丁味噌は大豆と塩だけで造る色の濃い味噌で」「江戸幕府を開いた家康は」)。
- 全体で160〜190字(100〜190字に収める)。
- 口調は「だ・である」の読みもの調。体言止めや「――」で余韻を出してよい。
- 事実は年・人名・数字まで確かめられるものだけ。言い伝えは「〜と伝わる」「〜という説がある」と書き分ける。営業時間・料金・混雑は書かない。閉業・閉館した場所を今もあるように書かない。

**みどころ(highlight)**

- 地名の由来、「日本初」、名物の意外なルーツ、景色に隠れた仕掛けなど、誰かに話したくなる事実。
- 「〇〇、△△が定番」のような羅列は書かない。
- 政令指定都市は、市の行には市全体の話、区の行にはその区ならではの話を書き、同じ話を使い回さない。

**怪奇・都市伝説(legend)**

- 2026-11-17 ユーザー指示:「毎回ネットで調べて興味深いものを選ぶ」。市区町村ごとに必ずネットを検索し、見つかった話の中から一番興味深いものを一つ選ぶ。
- 対象は、実在して、ネット上の複数のサイトで語られている話。怪談・心霊スポット・都市伝説のほか、その土地の伝説・民話・言い伝え(大蛇、河童、鬼、義経、弘法大師、七不思議、祟り、不思議な石や木など)、実在の事件や未解決の謎もよい。怖い話を優先し、無ければ不思議な話・伝説を選ぶ。
- 一番怖い場面・不思議な場面から始め、なぜそう語られるのか、どこに残っているか(神社・石・淵など)を続ける。言い伝えは「〜と伝わる」と書く。立入禁止の場所は「立入禁止」と添える。
- 検索しても語られている話が一つも無い街だけ、次の一文にする(市区町村名はマスタの表記のまま):
  `〇〇には、特に有名な怪談・都市伝説はありません。`
- 話をでっちあげない。一つのサイトにしか出てこない話、震災・事故の犠牲者を幽霊として扱う話は使わない。

## 作り方(スケジュール実行の1回分)

1回で1バッチ(約48市区町村)を作る。計画は `Trivia/plan.json`(40バッチ)。

1. 作業ブランチ `claude/project-thread-4nmqmc` を最新にする(`git fetch origin claude/project-thread-4nmqmc && git checkout -B claude/project-thread-4nmqmc origin/claude/project-thread-4nmqmc`)。
2. `python3 Trivia/scripts/next_batch.py` で次のバッチを出す。`Trivia/redo.json` に番号が残っていれば、そのバッチ(古い調べ方で作ったもの)を新しい調べ方で作り直す回になる。作り直しでは `Trivia/out/bNN.json` を上書きし、終わったら `redo.json` からその番号を消す。作り直しでは、みどころも都市伝説も、今の書き方(前提知識の説明つき、都市伝説は毎回ネットで調べる)で全市区町村を書き直す。今の文は材料として使ってよい。「全バッチ完了」なら何もせず終わる。
3. 市区町村ごとに材料を集める。general-purpose エージェント(WebSearch と WebFetch が使える)をバックグラウンドで8つ並べ、1つに6市区町村ずつ頼む。
   - 頼み方: 「各市区町村について WebSearch で『<都道府県><市区町村> 伝説』『<市区町村> 心霊スポット』『<市区町村> 民話 言い伝え』『<市区町村> 七不思議 都市伝説』などを検索し、出てきたページを WebFetch で読んで、ネットで語られている怪談・心霊・伝説・民話を候補として最大3つ挙げ、それぞれ要点(場所・年・人名)と載っていたURLを2つ以上添える。あわせて Wikipedia の記事(URL)から、地名の由来・名物の起源・日本初・意外な事実を年や数字ごと抜き出す。見つからなかったものは無いと書く」。
   - 今の文(出力の[今の…])は材料として使ってよいが、事実は確かめ直す。
   - 候補の中から一番興味深い話を選んで書く。
   - 調べものには上限がある(全エージェント共有で WebFetch は1時間100回、WebSearch は1ターン200回。WebSearch はタイトルとURLしか返さない)。1バッチ48市区町村で使い切らないよう、エージェントには「1市区町村につき WebSearch は4回まで、WebFetch は Wikipedia 1回+怪談・伝説のページ1回の計2回まで(48市区町村×2回で1時間100回にぎりぎり収まる。3回にすると途中で上限に当たる)。市区町村の伝説をまとめたページ(市の公式、観光協会、昔話のまとめ)を優先して読む。WebFetch が拒否されたり許可待ちになりそうなサイトは使わず、別のURLかタイトルだけで済ませる」と伝える。エージェントが許可待ちで3時間止まったことがあるので、次の回に止まったままなら止めて同じ市区町村で出し直す。
   - 上限で調べきれず「ありません」にした市区町村は `Trivia/legend_recheck.json` にコードを足す。全バッチが終わったら、ここに載った市区町村の都市伝説だけを調べ直す。

### 全バッチのあとの調べ直し

`next_batch.py` が「全バッチ完了」を出したら、1回につき48件ずつ都市伝説だけを調べ直す。

1. `python3 Trivia/scripts/next_recheck.py` で次の48件を出す(「ありません」の街が先、出典が弱い街があと)。「調べ直し完了」なら何もしない。
2. エージェント8つに6件ずつ頼む。回数は1市区町村につき WebSearch 5回まで、WebFetch は伝説ページ2回まで(Wikipediaは読まない)。旧町村名や大字での検索も試させる。
3. 結果を `Trivia/out/cNN.json` に書く。みどころは今の文をそのまま入れ、都市伝説だけを新しくする。良い話が無ければ定型文のままでよい(その街もファイルに入れて、調べ直し済みにする)。
4. `merge_trivia.py --check` → `merge_trivia.py` → コミットしてプッシュ。メッセージは `feat: 都市伝説を調べ直す(調べ直しNN)`。

4. `Trivia/out/bNN.json`(NNはバッチ番号2桁)に `{"行政区域コード": {"highlight": "...", "legend": "..."}}` の形で書く。途中で止まってもよいように、10市区町村ほど書くごとに保存する。
5. `python3 Trivia/scripts/merge_trivia.py --check` で確かめ、出た問題を直す。通ったら `python3 Trivia/scripts/merge_trivia.py` でマスタへ書き込む。
6. 変更は `Trivia/out/bNN.json` と `LocalGovernmentCodeJapan_Knowledge.csv` だけ。コミットして `git push origin claude/project-thread-4nmqmc` する。押し出しが拒否されたら `git pull --rebase origin claude/project-thread-4nmqmc` してマージをやり直してからプッシュする(CSVがぶつかったら、相手側を取ってから `merge_trivia.py` をもう一度実行する)。メッセージは `feat: みどころ・都市伝説を書き直す(バッチNN <最初の都道府県>〜)`。

やらないこと: アプリのコードの変更、マージ、TestFlightやApp Storeへのアップロード、依頼されていないバッチを先に進めること(1回1バッチ)。
